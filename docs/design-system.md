# plancel デザインの決まり（ボタンと配置）

`web/index.html` のスタイル末尾「ボタンの決まり」ブロックが実体。大きさをここ以外で足さない。
2026-11-11 に全 79 個を実測して決めた（直す前: 文字 6 種・高さ 7 種 28〜56px・太さ 3 種・角丸 4 種、
取り込みボタン以外はすべて 44px 未満）。

## ボタン

| 項目 | 決まり | 実体 |
|---|---|---|
| 大きさ | 標準と小の 2 つだけ | 標準 = 文字 `calc(16px * var(--fs))`・左右 16px。小 = `calc(14px * var(--fs))`・左右 12px |
| 高さ | どちらも 46px 以上（下限。文字サイズ「特大」では伸びる） | `--btn-h` |
| 太さ | すべて 600（選ばれた札・主の行ボタンも同じ。色と面で区別） | `--btn-fw` |
| 角丸 | すべて 999px（丸薬形） | `--btn-r` |
| 標準を使う所 | 主（`.btn-primary` `.btn-a`）・副（`.btn-ghost`）・選べる札（`.pol-mode` `.fs-opt`） | |
| 小を使う所 | 一覧の行の操作（`.rowbtn`）・見出しの小さなボタン（`.btn-small` `.btn-ghost.mini`）・上の切替（`.theme-toggle` `.fs-toggle`）・規定フォームの追加と削除（`.pol-add` `.pol-x`） | |
| アイコンだけ | 46×46px（`.avatar` `.x` `.iconbtn`） | |
| 見出しのアイコン | 明暗・文字サイズ・ベル・人は 1 つの見た目（地 `--card`・1px の枠・影なし・46px の丸）。色が変わるのは触れたときと選択中だけ | `.top-right` の 4 つ |
| カードの文字リンク | 「招待・編集・削除」は文字の見た目のまま、押せる範囲を 44px に。「·」で区切らず間隔で分ける（折り返すと「·」だけが行の端に残った） | `.resv .tools a` |
| 下のナビ | 項目は 48px 以上。取り込み（`.bn-fab`）は直径 56px、中身は＋の図形だけ（文字のラベルは置かない。読み上げ名は `aria-label`） | `.bn-item` |

文字の大きさを `:root` の変数にしない。`--fs`（文字サイズ切替）は `body` で決まるので、`:root` で
`calc(… * var(--fs))` を作ると無効な値になり、ボタンが親の文字サイズを継ぐ。

## 配置

- 見出し（上のバー）は 360px で 1 行。
- 連携（ベル）とマイページ（人）の入口は 1 画面に 1 か所。下のナビが出る幅（860px 以下）では下のナビに置き、
  見出しの 2 つは隠す。861px 以上では下のナビが出ないので見出しに置く。
- 横スクロールを出さない（`scrollWidth` = 画面幅）。
- 取り込み（主の行動）は下のナビの中央に常に見えている。

## 台帳の一覧（2026-11-13 に作り替え）

一覧は**日ごとの時系列**。旅行はそのまとまり（`section.trip`）で、旅行に入っていない予約は「旅行に入っていない
予約」の下に同じ形で並べる。何をすべきかは上の「今日やること」（`#rail`）が受け持ち、一覧は見渡すための場所にする。

- **1件1行**（`details.item`）。閉じた行に出すのは、時刻（`.i-when`。仮は「仮」の札、時刻未定は「未定」）・種類の札と
  名前・終わりの日／区間／金額／プラン名／共有元（`.i-sub`）・状態（`.i-st`：確定・候補・要キャンセル・案・未予約）と
  無料か安く戻せる日（`.i-dl.act`。強調する。もう高いときは強調せず「キャンセル料 n%」、規定不明は赤）・「同じ予約
  かも」の札。期限の棒・運賃と予約した人（`.facts`）・場所・キャンセル料の段階（`.sch-list`）・メモ・操作は、押して
  開いた中（`.i-body`）に置く。開いた行は、操作のあとに描き直しても開いたまま。
- **分けて取った予約の入れ子**（`.ride`）。同じ便・同じ宿・同じ駐車場を人数の内で分けて取ったものは、便を親に予約を
  入れ子で並べる（下の「人数」）。人数より多いものや人数の分からないものは、下の「どれか1つの囲み」に入れて比べる。
- **どれか1つの囲み**（`.alt`）。同じ夜の宿・同じ時間帯の便・同じ期間の駐車場と、2件以上のプランを1つの破線の囲みに
  入れる。見出しに名前（プラン名、または「同じ日程の宿」など）と「n件 · どれか1つに · 決めどき」、右に「比べる」。
  組のプランの兄弟（要キャンセルになったもの）も同じ囲みに入れて離さない。決まったら実線にして「決定済み」と出し、
  取り消しの連絡が残っていればそう書く。
- **希望順**（2026-11-13）。囲みの中は希望順（上ほど希望が高い）。左のつまみ（`.i-grip`。46px の正方形・読み上げ名つき）
  を押したまま上下に動かすと並べ替わり（指でもマウスでも。Pointer Events）、上下の矢印キーでも1つずつ動く。離したら
  上から 1, 2, 3… を予約の `rank` として保存するので、共有している人にも同じ順で見える。順の付いた行には「第n希望」の
  札（`.i-rank`）。並べ替えられるのは、囲みの生きている予約を全部書き換えられるとき（自分の予約か、編集を許可された
  共有）だけ。ドラッグ中の行は DOM の中で動かさない（動かすとポインターの捕捉が外れる）。入れ替わるのは隣の行。
- **提案**（2026-11-13）。共有された予約は、開いた中の「取り消しを提案」「確定を提案」（`.sug-box`）で持ち主に提案する。
  比べる画面で選んだときも、共有された予約には自動で提案が付く。持ち主には LINE（未連携ならメール）で一度だけ届き、
  持ち主の「今日やること」と行に「受ける（要キャンセルにする／確定する）」「そのままにする」が出る。確定と取り消しは
  持ち主だけのまま。状態が変われば提案は消える。行には「〜さんから取り消しの提案」「取り消しを提案中」の札。
- **旅行の見出し**に、日付の幅・件数・費用（確定と見込み）・決めること（件数と決めどき）・取り消しの連絡の件数を出す。
  見込みでは、どれか1つの囲みは1つとして数える。前は旅行の中に「行程」の一覧と全予約のカードを両方並べていて、
  同じ予約が2回出ていた（9件の旅行で 3,156px → 作り替えて 1,168px）。
- **今日やること**には、まだ決まっていない囲みを「〜を決める」として「比べる」付きで出す。決めどきが2日以内なら
  急ぎとして数える。見出しの件数は、急ぎでないものが並んでいるときは「急ぎ n件 / m件」と両方書く（「0件」と出して
  いるのに項目が並ぶ食い違いを出さない）。

## 人数（分けて取った予約・人数より多い予約。2026-11-13）

予約は「何人分か」（`people`）を、旅行は「何人で行くか」を持つ（旅行の見出しの「人数」、`src/web/trips.ts`）。旅行の
人数が無ければ、その旅行の予約の人数の最大から推定し、「（推定）」と書く。重なる予約の組はこの2つで読む
（`classifyAlternatives`。サーバ `src/web/overlap.ts`、画面の写しは `overlap_mirror_test.ts` が見張る）。

| 組の種別 | 条件 | 見せ方 |
|---|---|---|
| 分けて取った（split） | 人数の合計が旅行の人数以下 | 別々の便なら緑の実線の囲み「4人を2件に分けて予約（2人＋2人）· 全部使う」、同じ便・同じ宿なら便を親に予約を入れ子（`.ride`）。比べる・決めること・同じ予約かもの印は出さない。費用は全部足す |
| 人数より多い（over） | 合計が旅行の人数より多い | 破線の囲み「4人に8人分 · 4人分多い」。比べる画面の各列は「これを外す」（自分の予約は要キャンセル、共有は持ち主に提案） |
| どれか1つ（choose） | 人数が分からない予約がある | これまでどおり。宿と便の囲みには「それぞれの人数を入れると全部使う予約として扱います」と添える |

候補グループ（`plan`）は家族が「どれか1つ」と決めた束なので、人数では読まない。

- 同じ便・同じ宿・同じ駐車場を人数を分けて2回以上取ったもの（同じ名前・同じ日で、どれも人数が入っていて、合計が
  旅行の人数以下。旅行の人数が無ければ人数が入っているだけで分けて取ったと読む。同じ予約番号が2件あれば入れ直し
  とみなす — `classifyRide`）は、**便を親に、予約を入れ子に**見せる（`.ride`。オーナー 2026-11-13「最初から分けて
  取ったぶんはネストして見えるようにするべき」）。親に便のこと（時刻・種類の札・便名・区間・n人分・予約n件・合計金額・
  状態・いちばん早い無料か安く戻せる期限・足りない席・規定不明の件数）を1回だけ、下に予約ごとの行（`.item.bk`：左に
  人数、金額・予約番号・運賃・状態・期限）を左の線でぶら下げる。押すと予約ごとの詳細と操作。下に「＋この便の予約を
  足す」。同じ予約かもの印は出さない。
- 同じ便・同じ宿・同じ駐車場でも、人数より多い・人数が分からない・同じ予約番号が2件なら、入れ子にせず、時間の重なる
  便と同じく警告つきの比べる囲みに入れる（オーナー 2026-11-13「人数以上だったり時間が被ってたりしたら警告が出る比較
  対象になる」）。見出しは「4人に5人分 · **1人分多い**」「**同じ予約番号が2件** · 同じ予約の入れ直しかもしれません」
  「**同じ便が2件** · 人数が分からないので、どれか1つとして比べます」（太字は赤）。MCP の `overlaps` にも同じ組が
  over / choose で載る。
- 分けて取ったのに人数分に足りない（4人に2人＋1人）ときは、枠を赤にして「あと1人分足りない」と書き、今日やること
  と旅行の見出し（「席が足りない n件」）にも出す。MCP の `overlaps[].shortBy`。
- 人数より多い組の比べる画面では、各列に「外すと残り n人分」を出し、人数を割り込むなら「n人分足りなくなる」と書く。
- 1つの便・宿を人数や運賃ごとに別々に予約したら、予約ごとに1件ずつ登録する（人数・金額・予約番号はその予約の分）。
  アプリではフォームの「予約と料金」に予約の行を足す（「＋別に取った予約を足す」。便・宿・駐車場のときだけ出す）。
  編集で開くと、同じ便のほかの予約も行として並び、便のこと（名前・日時・区間・場所・旅行・時刻の仮）は全部の予約に
  そろえて保存する。規定は、この画面で変えたときだけ同じ運賃の予約にもそろえる。足した予約は1件目と同じ状態で、
  候補グループは付けない（候補グループ名がある予約には足せないと知らせる）。MCP は `create_reservation` の
  `bookings` に予約ごとの people・amount・ref（運賃・規定が違えばそれも）を並べて1回で登録する（予約ごとに1件）。
- 旅行の人数の推定では、同じ便を同じ日に分けて取った席を1つの一行の分として足す（2人＋2人は4人）。
- 便の組は、区間がそろっていれば「東京 → 小倉 の便」と区間で呼ぶ（行きと帰りの組が並んでも見分けられる）。

## 運賃・料金プランと、運賃の規定（2026-11-13）

予約は「運賃・料金プラン」（`fare`。例: JAL スペシャルセイバー、宿の夕朝食付きプラン）を持つ。JAL 国内線の運賃
（`src/web/fares.ts`。2026-11-13 に jal.co.jp の各運賃のページで確かめた12種類）を選ぶと、規定が不明なら
その運賃の取消規定を入れる。サーバが当てるので、フォームでも MCP でも同じ（MCP の応答は policySource "fare"）。
知っている運賃は、打ち方が違っても正式な名前（「JAL スペシャルセイバー」）で持つ。

- 航空会社が規定を変えることがある。フォームで規定を直し「この規定を『JAL スペシャルセイバー』の既定として保存」
  すると、その運賃の既定が上書きされ（施設の既定と同じ保存先。名前が運賃名）、以後はそちらが入る。マイページの
  保存した既定から消せば、公式の内容に戻る。
- 規定の形で表せないこと（出発後の手数料、出発20分前までの締切、料率が税抜運賃額に対すること）は、運賃を選んだ
  ときの注意書きに出す。保存した既定が入ったときは、そう言い、公式の内容は参考として分けて書く。
- 段階が1つで最初から有料の規定（セイバー: いつでも5%）は「いつでも5%」と言う（「当日5%」と言わない）。
- 予約番号（`ref`）と並べ、比べる画面に「運賃・料金プラン」「予約番号」の行を出す。

## メモに書かずに、目で見て分かる（2026-11-13）

オーナー「メモでなんでも説明すると入力の手間が大きすぎる」「メモに書くことが目で見てわかるようにすることが大事」。
最初の実データでは、席の内訳・運賃・規定の全文・出典の URL がメモに文で入っていた。決まった欄は欄として見せる。

- 予約の詳細の上に、欄を項目として並べる（`.facts`：人数・運賃・料金プラン・予約番号・予約した人）。
- キャンセル料は、この予約の日付と金額で段階を1行ずつ並べる（`.sch-list`。左に期間、右に料率と額。文字を大きくしても
  「いま」の印や額が割れないよう、表にはしない：「〜10/25(日) 5% ¥2,998」「10/26(月)〜12/19(土)
  12:05 50% ¥29,980」）。過ぎた段階は線で消し、いまの段階に「いま」。知っている運賃から入った規定なら、その運賃の
  補足（出発後の手数料・締切・税抜運賃額）と JAL の公式ページへのリンク（確かめた日つき）を添える。直してあれば
  「運賃の規定から直してあります」。
- フォームのメモの例と説明は「欄の無いことだけ」にする（例に予約番号や人数を書かない）。MCP の `notes` の説明も同じ。
- メモは **200字まで**（`src/web/notes.ts` の `NOTES_MAX`。オーナー 2026-11-13「200文字にしてください」）。アプリの API と
  MCP の作成・更新は超えると弾き（「メモは200字までです（人数・金額…はそれぞれの欄へ）」）、フォームは字数を出す
  （超えたら赤）。メール・スクショの読み取りは200字に切って渡す。前から長いメモは消さず、編集でメモに触れなければ
  そのまま残す。詳細では60字を超えるメモを3行に畳み、「全文を見る」で開く。

## カレンダーの日の印（2026-11-13）

オーナー「これ、数増えると表示崩れない？」。前は点を3つで切って ◆ を足していたので、4件目からは黙って消え、360px や
大きい文字では2段に折れて、その週だけマスが高くなっていた。

- 印は**1段に3つまで**（`.cal-marks` は折り返さない）。◆（無料キャンセル期限）があれば1つ使い、予約が入りきらなければ
  最後の1つを「+n」（`.cal-more`）にする。10件を超える日は点を出さず「+n」だけ（2桁で幅を取るため）。
- 点の並びは、要キャンセル → その日に始まる予約 → 滞在中。件数は読み上げ名（「12月19日 予約5件」）にも出し、凡例に
  「+2 ほかにも予約（日を押すと全部）」。日を押すと下に全部並ぶ。
- 360px・文字「特大」で、5件＋◆の日（「● +4 ◆」）と11件の日（「○ ○ +9」）が1段に収まり、マスの高さがそろうことを
  測った。

## 旅行の「予約がまだ」（2026-11-13）

オーナー「旅はきめたけど、予約がまだとかのtodoはあってもいいかも」。新しい種類は作らず、**確定・未予約**（「これに
決めた」＋「まだ予約していない」）の予約を、その旅行のやることとして見せる。候補のまま未予約のものは案なので入れない。

- 旅行の見出しの下（`.trip-tobook`）に「予約がまだ n件」と、日付・種類の札・名前と「予約した」を時刻順に並べる
  （見出しのやることの行には重ねて書かない）（共有された予約は持ち主の名前を添え、「予約した」は出さない。持ち主の操作）。
- その下に「＋予約項目を追加」。下の「＋」（取り込む）と同じ選び方を、その旅行の名前を持って開く（オーナー 2026-11-13
  「追加する方法もメールと画像はいるよね」）。メールの貼り付け・スクショ・写真の読み取り・手入力のどれでも旅行名が
  入り、旅行に関係のない転送・.ics・カレンダー連携は隠す。旅行から開いたときだけ「まだ予約していないものを足す
  （やること）」が出て、フォームを旅行名・「これに決めた」・「まだ予約していない」・旅行の初日・時刻未定で開く。
  フォームの見出しは「予約項目を追加」（オーナー「予約項目を追加が正しくない？」。前は「予約することを足す」）。
- フォームの言い方は「これに決めた（確定）」と「まだ予約していない」（前は「確定済みの予約」「まだ予約していない
  （検討中の案）」で、決めたが未予約という組み合わせが読めなかった）。
- 今日やることの「〇〇 を予約する」（確定・未予約）は今までどおり。MCP の `trips[].toBook` に同じものが載る。

## 安く戻れる期限の強調（2026-11-13）

オーナー「無料期間がなくても550円とか5%とかみたいに安めにキャンセルできる時はハイライトしたい。逆にもう何やっても
キャンセル料がかかる時は何もハイライトいらない」。手を打つ期限（`actDeadline`）は、無料で戻れる期限が先にあれば
それ、なければ**いまの段階が 10% 以下**（`CHEAP_PCT`、無料は除く）のときのその段階の終わり（`cheapUntil`）。

- 一覧の行・便の親の行: 「◆12/27(日)まで5%（¥2,000）」を無料の期限と同じ強調（`.i-dl.act`：ランプの濃い色・太字）。
- もう高い段階（無料期間なし・終了で、いまが 10% より上）は強調しない。行には「キャンセル料 50%」とだけ書き、棒の
  下は「いま取り消すと50%（¥14,000）」。前は「無料期間は終了」を赤で出していた。
- 棒の印・今日やること（2日以内の期限）・やることが無いときの一言・組の決めどき・比べる画面の期限の行も同じ期限を使う。
- 定額の手数料（550円など）は規定の形でまだ持てない（料率だけ）。サーバの通知・MCP の freeUntil は無料の期限のまま。

## ページ下の説明（保存先と安全）

利用者が気にするのは「どこに保存され、安全か」。一言の要約（サーバ＝Deno Deploy のデータベースに保存、見られるのは
自分と招待した人だけ）の下に、「保存先と安全について」を折りたたみで置く。中身は、コードで確かめたことだけを書く:
保存先（端末には予約の中身を残さない。service worker は `/api/` を保存しない）、見られる人（招待相手にもメール
アドレスは見せない、運営者は管理のためデータベースを見られる）、守り方（HTTPS、パスワードは PBKDF2 のハッシュ、
Google の鍵は AES-GCM で暗号化）、消すとき（退会で予約と共有の記録を消す）。仕組みを変えたら、ここも直す。

## 予約のフォーム

最初に**種類の札**（`.kind-chip`。標準の大きさの「選べる札」。もう一度押すと「指定なし」）を選ぶ。選んだ種類で、名前・
日付・時刻・終わりの日・区間の呼び方と例が切り替わる（宿＝チェックイン日／チェックアウト日、飛行機＝出発日／到着空港、
新幹線・電車＝乗車日／乗る駅・降りる駅、駐車場＝入庫日／出庫日 など。言い方は `KIND_FORM`、入力エラーの文も同じ
言い方）。項目は4つの節（`.fsec`）に分ける：種類と名前・区間 → 日時と場所 → 予約と料金（予約の行：人数・金額・運賃・予約番号、
キャンセル） → 状態・まとめ方・メモ。

## 旅行と予約の種類

- 旅行（`trip`）の見出しの下に、行程（時刻順の 1 行ずつ。時刻未定はその日の最後）と、その旅行のカードを並べる。
  見出しには日付の幅・件数・費用（確定の合計と、未確定を含む見込みの最大）を出す。
- 予約の種類（宿・食事・飛行機・電車・バス・車・駐車場・体験・その他）は名前の前の小さな札（`.kind`）で示す。交通と車は
  区間（出発地 → 到着地／借りる場所 → 返す場所）を 1 行で出す。駐車場は入庫（開始）〜出庫（終了）と場所で、区間は持たない。
- 状態の印は 2 種類: 「未予約」（まだ押さえていない案）と「仮」「時刻未定」（時刻が確かでない）。どちらも破線の
  札（`.tent`）で、確かなものと見分けがつくようにする。

## 同じ予約かもしれない組

同じ名前（空白・全角半角・大小は同一視）で同じ日の予約が複数あるとき、カードに破線の囲み（`.dup-note`）で
知らせる。自分のものと共有されたものをまたいで探す。知らせるだけで、登録・確定は止めない。「こちらにまとめる」
は、消す側が自分の予約で、残す側を自分が書き換えられる（自分の予約か、編集を許可された共有）ときだけ出す。

## 同じ日程に重なる宿・同じ時間帯に重なる便・同じ期間に重なる駐車場

同じ夜に別々の宿が重なっているとき（種類が宿、または種類なしで終わりが翌日以降）と、同じ時間帯に乗りものが
重なっているとき（飛行機・電車・バス。出発から到着まで、到着の時刻が無ければ 1 時間とみなす。時刻未定は入れない。
車は並行して借りるものなので入れない）、同じ期間に駐車場が重なっているとき（入庫日から出庫日まで、JST の日単位で両端を含む。
出庫が無い、または入庫より前なら入庫日の 1 日だけ。1 日でも重なれば組にする。出庫日に別の駐車場へ入れるような、順に使う駐車場も組になり、つながった分はまとめて 1 組になる）。いずれも候補か確定のもので、自分のものと共有されたものをまたいで探し、宿・便・駐車場は別々の組にする。知らせるだけで、
登録・確定は止めない。同じプランの候補どうし（プランの囲みが受け持つ）と、同じ名前・同じ日（「同じ予約かも
しれない組」が受け持つ）は対象にしない。判定の正は `src/web/overlap.ts`、画面の写しは `findOverlaps`
（`overlap_mirror_test.ts` が見張る）。

組は一覧の「どれか1つの囲み」（`.alt`。上の「台帳の一覧」）にまとめる。組に入った予約のプランの兄弟も同じ囲みに入れ、
どれかに旅行が付いていればその旅行の中に置く。旅行の費用の見込みでは、組は「どれか 1 つ」として数える（確定が
あれば候補は足さない。無ければいちばん高い候補だけ）。2件以上のプランも同じ囲み・同じ比較の画面を使う（題は
「『プラン名』の候補を比べる」）。

比較の画面（`#compareOverlay`）は、列 = 予約（要キャンセルになったものは外す）、行 = 比べる項目（金額と差額・無料で取り消せる期限・いま取り消すと・キャンセル規定・
日程・場所・メモ。便は「日程」の代わりに「時刻」と「区間」、名前の前に種類の札。駐車場は「期間」に入庫〜出庫を時刻つき（時刻が無ければ日付だけ。フォームの出庫は日付だけで 23:59 に保存されるので、23:59 も日付だけとして出す）で出し、名前の前に種類の札。題は「同じ期間の駐車場を比べる」）。項目名は列をまたぐ 1 行（`.cmp-label`）にして、360px でも値の列を広く取る。上に「決めどき」
（組の中でいちばん早い無料期限。`.decide-note`）を出す。「こちらに決める」（`.rowbtn.confirm`）は名前のすぐ下に
置き、最初の画面に入れる。押す前に、何が確定し何が要キャンセル（未予約の案は見送り）になるかを名指しで確かめる。
確定と取り消しは持ち主だけなので、共有された予約は変わらず、誰に頼むかを文で出す。押しても何も変わらない列には
ボタンを出さない。
